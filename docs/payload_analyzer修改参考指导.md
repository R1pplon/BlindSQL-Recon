# AI 驱动的盲注配置自动化生成框架
## 一、 核心思想与方法论
本项目旨在解决 `BlindSQL-Recon` 中配置文件 (`yaml`) 编写门槛高、依赖人工经验的问题。通过引入 AI，实现从“流量样本”到“分析配置”的自动化映射。
### 1. 方法论：抽象-转换-验证
*   **抽象**：从海量日志中剥离噪声，提取核心特征（统计特征、结构特征）。
*   **转换**：利用大模型（LLM）的语义理解能力，将特征映射为符合 `sqlmap_analyzer.py` 规范的代码（正则表达式、逻辑判断）。
*   **验证**：利用盲注攻击的“二分法收敛”特性，建立确定性的闭环校验机制，确保 AI 输出的“零误差”。
### 2. 核心逻辑支点：二分法收敛特性
盲注攻击（尤其是布尔盲注）基于二分查找算法。这意味着：
*   **逻辑严密性**：正确的配置能还原出完整的 ASCII 字符序列。
*   **容错率为零**：任何配置偏差（如正则少一个括号、判断阈值错误）都会导致还原结果变为乱码或完全失败。
*   **利用价值**：这一特性使我们能够编写脚本自动判断配置的正确性，无需人工复核，从而实现“AI 生成 -> 自动测试 -> 自动修正”的完整闭环。

## 二、 架构设计：三阶段流水线
整个生成流程设计为三个独立模块，通过标准数据结构传递信息。
### 阶段一：特征提取器
**目标**：将非结构化日志压缩为 AI 可理解的高维特征摘要。
**输入**：原始 JSON 行数据（含 `payload`, `response_size`）。
**处理逻辑**：
1.  **响应聚类**：统计 `response_size` 分布，识别“双峰分布”。提取疑似 True/False 的阈值区间。
2.  **样本采样**：筛选具有代表性的 Payload 样本（去除重复，保留结构差异大的样本）。
3.  **关键词频率分析**：初步统计 Payload 中高频词汇，辅助确定 `trigger_pattern`。
**输出**：结构化的特征摘要对象（JSON 格式）。
### 阶段二：语义转换器
**目标**：基于特征摘要，生成符合 `BlindAnalysisConfig` 规范的 YAML 配置。
**核心技术**：Prompt Engineering。
**设计原则**：
*   **Schema 约束**：Prompt 必须明确包含目标 YAML 的字段定义，强制 AI 输出可解析的结构。
*   **思维链引导**：引导 AI 先分析注入类型，再编写正则，最后确定判断逻辑。
*   **正则转义强调**：明确要求 AI 处理正则中的特殊字符转义（如 `\s`, `\d`），这是 AI 极易出错点。
### 阶段三：闭环校验器
**目标**：确定性验证生成配置的有效性，负责错误反馈与重试。
**输入**：生成的 YAML 配置字符串 + 原始样本数据。
**处理逻辑**：
1.  **语法加载测试**：尝试实例化 `BlindAnalysisConfig`，捕获语法错误。
2.  **匹配率测试**：运行 `sqlmap_analyzer.py` 核心逻辑，检查 `type` 是否为 `unknown`。若匹配率过低，判定 `trigger_pattern` 或正则错误。
3.  **逻辑完备性测试**：检查提取出的 `database`, `table`, `column` 是否为空。
4.  **ASCII 有效性测试**：检查提取的 `ascii_value` 是否在常见字符区间（32-126）。
**反馈机制**：若测试失败，将具体的错误信息追加到 Prompt 中，要求 AI 重新生成（最大重试次数限制为 3 次）。

## 三、 执行标准与规范
### 1. 配置字段映射规范
AI 必须严格遵循以下映射关系生成配置：
*   `trigger_pattern`: 必须是 Payload 中**唯一且稳定**的特征子串（通常为 SQL 函数头，如 `ORD(MID(`）。
*   `judge_function`:
    *   若响应大小呈现明显的二元对立，优先生成 `size_equal` 或 `size_less`。
    *   必须输出具体的数值 (`value`)。
*   `patterns`:
    *   必须包含捕获组 `(...)`。
    *   `from_pattern` 需捕获两个组。
    *   `comparison_pattern` 需捕获运算符和数值。
### 2. 数据流接口规范
为了模块解耦，各阶段间应通过标准 JSON 传递：
*   **输入**：`{"payload": "...", "response_size": int}`
*   **中间态（特征摘要）**：`{"samples": [...], "size_stats": {"peak_a": 15, "peak_b": 2000}}`
*   **输出**：纯文本 YAML 字符串。
### 3. 错误处理策略
*   **重试策略**：采用指数退避或固定次数重试。
*   **降级策略**：若 AI 多次生成失败，输出模板配置 (`analyzer_config.yaml`) 并提示用户手动修改，确保管道不中断。
---
## 四、 实施路线图
1.  **原型开发**：编写特征提取脚本和 Prompt 模板，手动调用 LLM API 验证生成效果。
2.  **集成开发**：开发闭环校验模块，集成 `sqlmap_analyzer.py` 的核心类进行自动化测试。
3.  **管道嵌入**：在 `3_payload_analyzer/` 下创建 `ai_config_generator.py`，作为管道的可选前置步骤。
4.  **模型微调（可选）**：收集生成过程中的正确/错误案例，构建 Few-Shot Prompt 库，提升生成成功率。
此框架明确了“数据预处理-Prompt工程-闭环验证”三位一体的实施路径，利用盲注逻辑的严密性解决 AI 生成的不确定性问题，是后续开发的指导性文件。
